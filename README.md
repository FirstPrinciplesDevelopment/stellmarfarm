# Getting started

### Developing in GitHub Codespaces (recommended)

The codespace will run `npm install` and `npm run dev` automatically. It may take a minute or two, but once it has started up, click "Open in Browser" to open the site in a new tab. It will hot reload (automatically update) as you make changes. See the video below for reference.


https://github.com/FirstPrinciplesDevelopment/stellmarfarm/assets/38818928/3c26eebc-9a62-48dc-bede-6874c0ef0893


### Developing Locally


1. Install [Node.js 20](https://nodejs.org/en), [git](https://git-scm.com/downloads), and an editor such as [VS Code](https://code.visualstudio.com/).

2. Clone this git repository and open it in your editor.
    ```sh
    git clone https://github.com/FirstPrinciplesDevelopment/stellmarfarm.git
    ``` 

3. Install dependencies.
    ```sh
    npm install
    ```
    
4. Use parcel to build and start development server.

    ```sh
    npm run dev
    ```

5. Browse to [localhost:1234](http://localhost:1234). As you make edits, parcel will rebuild and hot reload the page.



# More Information

### Tailwind CSS

[Tailwind CSS](https://tailwindcss.com/) is a CSS framework with [great documentation](https://tailwindcss.com/docs/utility-first).

### Parcel

[Parcel](https://parceljs.org/) is used to
- copy all your HTML, CSS and JS from src/ to dist/,
- use [tailwindcss](https://tailwindcss.com/) to scan your source code and compile the minimal CSS for tailwind classes you use, see [the docs](https://tailwindcss.com/docs/guides/parcel),
- start a development server that rebuilds and hot reloads the page in your browser when you make changes in src/.

### Directory Structure

```
.github/
src/
.gitignore
.postcssrc
package-lock.json
package.json
README.md
tailwind.config.js
```

- **.github/** contains definitions of ***workflows*** also called ***actions*** that can, among other things, deploy every time you push new code to GitHub.
- **src/** contains the HTML, JS and CSS that you can edit.


# Preparing for A New Year

1. Create a new Supbase Project called "20XX Monster Vote".
    - Don't connect GitHub, no need for this.
    - Database password: reuse from last year or create a new one and save it (won't actually need this for anything).
    - Region: "Canada (Central)"
    - ✅ Enable Data API
    - ✅ Automatically expose new tables
    - ✅ Enable automatic RLS

2. Create `monsters` and then `votes` tables plus their security policies by running the following SQL in the Supabase "SQL Editor". You should see "Success. No rows returned" or something like that.

```sql
-- monsters table
create table public.monsters (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text null,
  business text null,
  season smallint not null,
  image_url text null,
  position integer not null default 0,
  constraint monsters_pkey primary key (id)
) TABLESPACE pg_default;

-- monsters table RLS (row-level security) policies
-- allow public reads
create policy "Enable read access for public users"
on "public"."monsters"
as PERMISSIVE
for SELECT
to public
using (
    true
);
-- grant dashboard_user (in the Supbase UI) all permissions
create policy "Enable all for dashboard_user only"
on "public"."monsters"
as PERMISSIVE
for ALL
to dashboard_user
using (
    true
);

-- votes table -- depends on monsters table 
create table public.votes (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  email text null,
  name text null,
  favorite_monster bigint not null,
  contact_consent boolean not null default false,
  constraint votes_pkey primary key (id),
  constraint public_votes_favorite_monster_fkey foreign KEY (favorite_monster) references monsters (id) on update CASCADE on delete CASCADE
) TABLESPACE pg_default;

-- votes table RLS (row-level security) policies
-- allow public inserts
create policy "Enable insert for public users"
on "public"."votes"
as PERMISSIVE
for INSERT
to public
with check (
    true
);
-- grant dashboard_user (in the Supbase UI) all permissions
create policy "Enable all for dashboard_user only"
on "public"."votes"
as PERMISSIVE
for ALL
to dashboard_user
using (
    true
);

```

3. Create a Supabase storage bucket called "monsters".
    - In the Supbase UI, go to **Storage** and click **+ New Bucket**.
    - Name is "monsters" and make it "public".
    - You will upload your monster images to this bucket, then copy the URL that Supabase provides (click the image in the Supabase UI, then "Get URL"). That URL is what you should insert for the `image_url` column of the corresponding row in the `monsters` table.

4. Add your monster photos and data (can do now or later, nice to add at least one test row and photo). The Supabase "Table Editor" is usable to manually create the small number of rows, you could also try a CSV upload.

5. View the Supabase "Connect" options. `SUPABASE_URL` AND `SUPABASE_PUBLISHABLE_KEY` are the two values we need for the website to connect to Supabase.
    > Note: You may need to select the "Server | Build APIs" tab in the "Connect" options panel to see these variables.
    - We will update src/components/vote/vote.js. Substitute those values plus the current year to set the following constants (around line 9).

```js
// Constants for public API.
const anon_api_key = "SUPABASE_PUBLISHABLE_KEY";
const api_base_url = "SUPABASE_URL";
const year = 2026;
```

6. Commit and push to GitHub, then deploy your website changes (not sure what your technique is for this at the moment).
